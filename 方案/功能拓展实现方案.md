## 二、30天TTL设计决策总览

```
┌────────────────────────────────────────────────────────────────┐
│                    TTL = 30天 = 2592000秒                       │
│                                                                 │
│  每次【写操作】自动重置 TTL，确保活跃数据不过期                    │
│  每次【读操作】先检查 Key 是否存在，不存在则跳过（惰性清理）       │
│                                                                 │
│  有 TTL 的 Key:                                                 │
│    ✅ diary:{id}             日记实体                            │
│    ✅ conv:{id}              对话实体                            │
│    ✅ conv:{id}:messages     对话消息列表                        │
│    ✅ user:{userId}:diaries  用户日记索引                        │
│    ✅ user:{userId}:convs    用户对话索引                        │
│                                                                 │
│  无 TTL 的 Key（全局序列，永不过期）:                             │
│    ❌ seq:diary:id           日记ID自增序列                      │
│    ❌ seq:conv:id            对话ID自增序列                      │
└────────────────────────────────────────────────────────────────┘
```

> **核心原则**：同一个用户的所有数据共享同一个 30 天生命周期——只要用户保持活跃（写日记/聊天），所有关联 Key 的 TTL 都会被续期，数据不会丢失。连续 30 天不活跃后，数据自动清理。

## 五、Redis 数据模型设计（含 TTL 策略）

### 5.1 日记 (`Diary`)

```
┌─────────────────────────────────────────────────────┐
│ Key:    diary:{diaryId}                             │
│ Type:   String (JSON)                               │
│ TTL:    30天 ── 创建/更新时重置                      │
│                                                     │
│ Value:                                              │
│ {                                                   │
│   "id": "d_001",                                    │
│   "userId": "default_user",                         │
│   "title": "今天的心情",                              │
│   "content": "今天天气很好，出去走了走...",            │
│   "mood": "happy",                                  │
│   "createdAt": 1716624000000,                       │
│   "updatedAt": 1716624000000                        │
│ }                                                   │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│ Key:    user:{userId}:diaries                       │
│ Type:   Sorted Set                                  │
│ TTL:    30天 ── 每次添加/更新成员时重置               │
│ Score:  updatedAt 毫秒时间戳                         │
│ Member: diaryId                                     │
│                                                     │
│ 操作示例:                                            │
│ ZADD user:default_user:diaries 1716624000000 d_001  │
│ EXPIRE user:default_user:diaries 2592000             │
└─────────────────────────────────────────────────────┘
```

**TTL 行为表**：

| 操作 | `diary:{id}` TTL | `user:{userId}:diaries` TTL |
|------|:---:|:---:|
| 创建日记 | 设置 30天 | 设置 30天 |
| 更新日记 | **重置** 30天 | 不重置（score会更新，但TTL不主动续） |
| 删除日记 | N/A | 移除 member（不重置TTL） |
| 读取日记 | 不重置 | 不重置 |

> **设计决策**：更新日记时只重置实体 Key 的 TTL，不重置索引 Key 的 TTL。原因：索引可能包含多个日记，单个日记更新不应让整个索引"续命"。索引的 TTL 由**创建新日记**或**专门的定时任务**来续期。实际上，当用户创建任何新日记时，索引 Key 的 TTL 都会被重置——只要用户保持活跃，就不会丢索引。

### 5.2 对话 (`Conversation`)

```
┌─────────────────────────────────────────────────────┐
│ Key:    conv:{convId}                               │
│ Type:   String (JSON)                               │
│ TTL:    30天 ── 创建/发消息时重置                     │
│                                                     │
│ Value:                                              │
│ {                                                   │
│   "id": "c_001",                                    │
│   "userId": "default_user",                         │
│   "title": "关于焦虑的聊天",                          │
│   "createdAt": 1716624000000,                       │
│   "updatedAt": 1716624000000                        │
│ }                                                   │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│ Key:    conv:{convId}:messages                      │
│ Type:   List                                        │
│ TTL:    30天 ── 每次追加消息时重置                    │
│                                                     │
│ Element (JSON):                                     │
│ {                                                   │
│   "role": "USER",                                   │
│   "content": "最近总是很焦虑...",                     │
│   "timestamp": 1716624000000                        │
│ }                                                   │
│ {                                                   │
│   "role": "ASSISTANT",                              │
│   "content": "【情绪】anxious\n【回复】...",          │
│   "timestamp": 1716624010000                        │
│ }                                                   │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│ Key:    user:{userId}:convs                         │
│ Type:   Sorted Set                                  │
│ TTL:    30天 ── 创建新对话/发消息时重置               │
│ Score:  updatedAt 毫秒时间戳                         │
│ Member: convId                                      │
└─────────────────────────────────────────────────────┘
```

**TTL 行为表**：

| 操作 | `conv:{id}` TTL | `conv:{id}:messages` TTL | `user:{userId}:convs` TTL |
|------|:---:|:---:|:---:|
| 创建对话 | 设置 30天 | (无消息) | 设置 30天 |
| 发送消息 (含AI回复) | **重置** 30天 | **重置** 30天 | **重置** 30天 |
| 重命名对话 | **重置** 30天 | 不重置 | 不重置 |
| 删除对话 | N/A | N/A | 移除 member |
| 查看对话 | 不重置 | 不重置 | 不重置 |

> **关键设计**：因为聊天是核心交互，每次发消息时三个关联 Key 同时续期——这是合理的，确保活跃对话不会丢数据。

### 5.3 全局 ID 序列（无 TTL）

```
Key:    seq:diary:id      Type: String     Value: "5"     TTL: 无
Key:    seq:conv:id       Type: String     Value: "12"    TTL: 无
```

使用 Redis `INCR` 命令原子自增，生成唯一 ID。全局序列永不过期，保证 ID 永远递增不重复。

### 5.4 定时清理辅助设计（惰性清理）

由于 Sorted Set 中的 member 引用的实体 Key 可能**先于索引过期**，会出现**孤儿引用**问题。

**解决方案**：读时惰性清理：

```
读取日记列表时:
  1. ZREVRANGE user:{userId}:diaries (获取 member 列表)
  2. 遍历 member，对每个 diaryId:
     a. EXISTS diary:{diaryId}          → 存在则收集
     b. 不存在（已过期）                  → ZREM 移除孤儿引用
  3. 返回有效日记列表
  4. 如果清理后列表为空，EXPIRE 索引 Key（避免空 Key 残留）
```

```java
public class RedisConstants {

    /** 全局TTL：30天（秒） */
    public static final long DEFAULT_TTL_SECONDS = 30 * 24 * 60 * 60; // 2592000

    /** Key 前缀 */
    public static final String DIARY_KEY_PREFIX = "diary:";
    public static final String USER_DIARIES_KEY_PREFIX = "user:";
    public static final String USER_DIARIES_KEY_SUFFIX = ":diaries";
    public static final String CONV_KEY_PREFIX = "conv:";
    public static final String CONV_MESSAGES_SUFFIX = ":messages";
    public static final String USER_CONVS_KEY_PREFIX = "user:";
    public static final String USER_CONVS_KEY_SUFFIX = ":convs";
    public static final String SEQ_DIARY_ID = "seq:diary:id";
    public static final String SEQ_CONV_ID = "seq:conv:id";

    /** ID前缀 */
    public static final String DIARY_ID_PREFIX = "d_";
    public static final String CONV_ID_PREFIX = "c_";

        return DIARY_KEY_PREFIX + diaryId;

        return USER_DIARIES_KEY_PREFIX + userId + USER_DIARIES_KEY_SUFFIX;

        return CONV_KEY_PREFIX + convId;
```

## 九、核心 Repository 设计

### 9.1 DiaryRepository — 关键方法伪代码

```java
@Repository
public class DiaryRepository {

    private final StringRedisTemplate redis;
    private final ObjectMapper objectMapper;

    // 生成ID: INCR seq:diary:id → "d_" + id
    public String nextId() { ... }

    // 创建日记
    public Diary save(Diary diary) {
        String key = diaryKey(diary.getId());
        String json = objectMapper.writeValueAsString(diary);
        redis.opsForValue().set(key, json, DEFAULT_TTL_SECONDS, TimeUnit.SECONDS);
        // 更新索引
        redis.opsForZSet().add(userDiariesKey(diary.getUserId()), diary.getId(), diary.getUpdatedAt());
        redis.expire(userDiariesKey(diary.getUserId()), DEFAULT_TTL_SECONDS, TimeUnit.SECONDS);
    }

    // 查询单篇
    public Optional<Diary> findById(String diaryId) {
        String json = redis.opsForValue().get(diaryKey(diaryId));
        if (json == null) return Optional.empty();  // 已过期
        return Optional.of(objectMapper.readValue(json, Diary.class));
    }

    // 更新日记 (含TTL重置)
    public void update(Diary diary) {
        String key = diaryKey(diary.getId());
        String json = objectMapper.writeValueAsString(diary);
        // 设置值并重置TTL
        redis.opsForValue().set(key, json, DEFAULT_TTL_SECONDS, TimeUnit.SECONDS);
        // 更新索引中的时间戳
        redis.opsForZSet().add(userDiariesKey(diary.getUserId()), diary.getId(), diary.getUpdatedAt());
    }

    // 分页列表 (含惰性清理)
    public PageResult<Diary> findByUserId(String userId, int page, int size) {
        String indexKey = userDiariesKey(userId);
        // ZREVRANGE 按时间倒序，手动分页
        Set<String> diaryIds = redis.opsForZSet().reverseRange(indexKey, (page-1)*size, page*size-1);
        Long total = redis.opsForZSet().zCard(indexKey);

        List<Diary> diaries = new ArrayList<>();
        for (String id : diaryIds) {
            Optional<Diary> opt = findById(id);
            if (opt.isPresent()) {
                diaries.add(opt.get());
            } else {
                // 惰性清理孤儿引用
                redis.opsForZSet().remove(indexKey, id);
            }
        }
        return new PageResult<>(diaries, total, page, size);
    }

    // 删除
    public void delete(String diaryId, String userId) {
        redis.delete(diaryKey(diaryId));
        redis.opsForZSet().remove(userDiariesKey(userId), diaryId);
    }
}
```

### 9.2 ConversationRepository — 关键方法伪代码

```java
@Repository
public class ConversationRepository {

    // 创建对话
    public Conversation save(Conversation conv) {
        String key = convKey(conv.getId());
        String json = objectMapper.writeValueAsString(conv);
        redis.opsForValue().set(key, json, DEFAULT_TTL_SECONDS, TimeUnit.SECONDS);
        redis.opsForZSet().add(userConvsKey(conv.getUserId()), conv.getId(), conv.getUpdatedAt());
        redis.expire(userConvsKey(conv.getUserId()), DEFAULT_TTL_SECONDS, TimeUnit.SECONDS);
    }

    // 追加消息 + 重置TTL（核心方法）
    public void appendMessage(String convId, String userId, ChatMessageVO message) {
        String msgKey = convMessagesKey(convId);
        String json = objectMapper.writeValueAsString(message);
        redis.opsForList().rightPush(msgKey, json);
        // 三个Key同时续期！
        redis.expire(convKey(convId), DEFAULT_TTL_SECONDS, TimeUnit.SECONDS);
        redis.expire(msgKey, DEFAULT_TTL_SECONDS, TimeUnit.SECONDS);
        redis.expire(userConvsKey(userId), DEFAULT_TTL_SECONDS, TimeUnit.SECONDS);
    }

    // 查询消息列表
    public List<ChatMessageVO> findMessages(String convId) {
        String msgKey = convMessagesKey(convId);
        List<String> jsonList = redis.opsForList().range(msgKey, 0, -1);
        if (jsonList == null || jsonList.isEmpty()) return List.of();  // 已过期或空
        return jsonList.stream()
                .map(j -> objectMapper.readValue(j, ChatMessageVO.class))
                .toList();
    }

    // 重命名 + 重置TTL
    public void updateTitle(String convId, String title) {
        String key = convKey(convId);
        String json = redis.opsForValue().get(key);
        if (json == null) throw new NotFoundException("对话不存在或已过期");
        Conversation conv = objectMapper.readValue(json, Conversation.class);
        conv.setTitle(title);
        conv.setUpdatedAt(System.currentTimeMillis());
        String newJson = objectMapper.writeValueAsString(conv);
        redis.opsForValue().set(key, newJson, DEFAULT_TTL_SECONDS, TimeUnit.SECONDS);
    }

    // 删除
    public void delete(String convId, String userId) {
        redis.delete(convKey(convId));
        redis.delete(convMessagesKey(convId));
        redis.opsForZSet().remove(userConvsKey(userId), convId);
    }
}
```

## 十、RedisChatMemoryStore — LangChain4j 记忆持久化

这是连接 LangChain4j 上下文窗口与 Redis 的关键桥梁：

```java
@Component
public class RedisChatMemoryStore implements ChatMemoryStore {

    private final StringRedisTemplate redis;
    private final ObjectMapper objectMapper;
    private static final int MAX_MESSAGES = 10; // 窗口大小

    @Override
    public List<ChatMessage> getMessages(Object memoryId) {
        String key = convMessagesKey(memoryId.toString());
        // 取最近10条消息作为上下文窗口

                .filter(Objects::nonNull)
                .toList();
    }

        // 这里只需保持 ChatMemoryStore 的内部状态即可
    }
```

```java
@Configuration
public class RedisConfig {

    @Bean
    public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(factory);

        // Key 用 String 序列化
        StringRedisSerializer stringSerializer = new StringRedisSerializer();
        template.setKeySerializer(stringSerializer);
        template.setHashKeySerializer(stringSerializer);

        // Value 用 Jackson JSON 序列化
        Jackson2JsonRedisSerializer<Object> jsonSerializer =
                new Jackson2JsonRedisSerializer<>(Object.class);
        ObjectMapper mapper = new ObjectMapper();
        mapper.registerModule(new JavaTimeModule());
        mapper.disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS);
        jsonSerializer.setObjectMapper(mapper);

        template.setValueSerializer(jsonSerializer);
        template.setHashValueSerializer(jsonSerializer);
        template.afterPropertiesSet();
        return template;
    }

    // StringRedisTemplate 用于手动 JSON 操作（Repository 层主要使用这个）
    @Bean
    public StringRedisTemplate stringRedisTemplate(RedisConnectionFactory factory) {
        return new StringRedisTemplate(factory);
    }
}
```

## 十四、SoulComfortController 改造

```java
@RestController
@RequestMapping("/soulComfort")
public class SoulComfortController {

    @Resource
    private SoulComfortService soulComfortService;

    @Resource
    private ConversationService conversationService;

    // 改造后：用 convId 替代 memoryId，增加 userId
    @GetMapping(value = "/chat", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<String>> chat(
            @RequestParam String convId,
            @RequestParam String userId,
            @RequestParam String message) {

        // 1. 先异步保存用户消息到Redis
        conversationService.appendUserMessage(convId, userId, message);

        // 2. 发送思考状态
        Flux<ServerSentEvent<String>> thinkingFlux = Flux.just(
                ServerSentEvent.<String>builder()
                        .event("status")
                        .data("\uD83C\uDF3F 甜弈正在感受你的心情...")
                        .build()
        );

        // 3. 流式聊天 + 收集完整回复
        StringBuilder fullResponse = new StringBuilder();
        Flux<ServerSentEvent<String>> chatFlux = soulComfortService
                .chatStream(parseConvIdToLong(convId), message)
                .map(chunk -> ServerSentEvent.<String>builder()
                        .data(chunk)
                        .build())
                .doOnNext(event -> {
                    if (event.data() != null) {
                        fullResponse.append(event.data());
                    }
                })
                .doOnComplete(() -> {
                    // 4. 流结束后保存完整AI回复
                    conversationService.appendAssistantMessage(convId, userId, fullResponse.toString());
                })
                .doOnError(e -> {
                    log.error("聊天异常 convId={}", convId, e);
                });

        return Flux.concat(thinkingFlux, chatFlux);
    }

    // convId (c_xxx) → memoryId (long for LangChain4j)
    private long parseConvIdToLong(String convId) {
        // 去掉 "c_" 前缀，将剩余部分转为 long（作为 LangChain4j @MemoryId）
        return Long.parseLong(convId.substring(2));
    }
}
```

## 十六、TTL 过期场景与容错处理

| 场景 | 表现 | 处理方式 |
|------|------|---------|
| 用户30天未活跃 | 所有数据Key过期，Redis自动删除 | 用户再次使用视为新用户，前端引导创建新对话 |
| 查询已过期对话 | `conv:{id}` 返回 null | 返回 404 + "对话不存在或已过期" |
| 索引有孤儿引用 | 列表查询时某些实体Key已过期 | 惰性清理：遍历时 `EXISTS` 检查，`ZREM` 移除 |
| 用户发消息到过期对话 | RPUSH 时 Key 不存在 | Redis 自动创建空 List + 设置 TTL，无异常 |
| 30天内活跃用户 | 每次写操作续期TTL | 数据永久保持（只要30天内有活动） |
