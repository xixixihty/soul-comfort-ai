# 用户认证系统 — 功能拓展实现方案

## 一、方案概述

在纯 Redis 存储架构下实现用户注册/登录 + JWT 无状态认证。所有现有功能（聊天记录、日记、对话）与真实用户 ID 绑定。

---

## 二、技术选型

| 层面 | 选型 | 理由 |
|------|------|------|
| 密码哈希 | **BCrypt** | 内置支持，防彩虹表，cost=10 |
| 令牌方案 | **JWT (HMAC-SHA256)** | 无状态，无需 Redis 存储 session，适合当前架构 |
| 令牌传递 | `Authorization: Bearer <token>` | RESTful 标准 |
| 后端拦截 | **HandlerInterceptor** | 轻量级，比 Spring Security 更可控 |
| 前端状态 | **Vue reactive + localStorage** | 项目依赖极简，不引入 Pinia |
| 令牌存储 | `localStorage` | 简单直接 |

> **为什么不引入 Spring Security？**
> 当前项目是纯 Redis 单体应用，无复杂 RBAC。Spring Security 的 Filter Chain + SecurityContext 对简单 JWT 场景过重，反而增加调试成本。`HandlerInterceptor` + 手动 JWT 校验完全够用。

## 三、数据模型设计

### 3.1 Redis Key 设计

| Key 模式 | 类型 | 内容 | TTL |
|----------|------|------|-----|
| `user:{userId}` | Hash | username, passwordHash, createdAt | **永不过期** |
| `user:index:username:{username}` | String → userId | 用户名唯一索引 | **永不过期** |
| `seq:user:id` | String (自增) | 用户 ID 序列 | 永不过期 |

> **关键设计**：用户数据**不设 TTL**，确保账户不会自动消失。这是 user 和业务数据（30 天）分层 TTL 的良好实践。

### 3.2 实体类

```java
// User.java
public class User {
    private String id;          // "u_1", "u_2" ...
    private String username;    // 唯一，3~20字符
    private String passwordHash;// BCrypt 哈希
    private long createdAt;     // 注册时间戳
}
```

### 3.3 ID 生成

格式 `u_1`, `u_2`, ...，通过 `INCR seq:user:id` 自增。

## 四、接口契约

### 4.1 POST `/api/auth/register` — 注册

```
Request:
{
    "username": "zhangsan",    // 必填, 3~20字符, 字母/数字/下划线
    "password": "123456"       // 必填, 6~32字符
}

Response (200):
{
    "code": 0,
    "msg": "success",
    "data": {
        "token": "eyJhbGciOi...",
        "user": {
            "id": "u_1",
            "username": "zhangsan"
        }
    }
}

Response (400):
{
    "code": 1001,
    "msg": "用户名已存在",
    "data": null
}
```

### 4.2 POST `/api/auth/login` — 登录

```
Request:
{
    "username": "zhangsan",
    "password": "123456"
}

Response (200):
{
    "code": 0,
    "msg": "success",
    "data": {
        "token": "eyJhbGciOi...",
        "user": {
            "id": "u_1",
            "username": "zhangsan"
        }
    }
}

Response (401):
{
    "code": 1002,
    "msg": "用户名或密码错误",
    "data": null
}
```

### 4.3 JWT Payload 结构

```json
{
    "sub": "u_1",           // 用户ID
    "username": "zhangsan", // 用户名
    "iat": 1716652800,      // 签发时间
    "exp": 1719244800       // 过期时间 (30天)
}
```

签名算法：HMAC-SHA256

### 5.2 拦截器机制

```
请求流程：
Client → [LoginInterceptor] → Controller
               │
               ├─ 路径匹配 /auth/** → 放行
               │
               └─ 其他路径 → 解析 Authorization Header
                              │
                              ├─ 无token → 401
                              ├─ token过期 → 401
                              ├─ token无效 → 401
                              └─ 校验通过 → UserContext.set(userId)
                                           → Controller 通过 UserContext.getUserId() 获取
```

### 5.3 Controller 改造方式

**改造前：**
```java
private static final String DEFAULT_USER_ID = "default_user";
diaryService.create(DEFAULT_USER_ID, ...);
```

**改造后：**
```java
diaryService.create(UserContext.getUserId(), ...);
```

将 `DEFAULT_USER_ID` 常量全部替换为 `UserContext.getUserId()`。

### 5.4 API 白名单

以下路径不走 Interceptor：
- `/auth/**` — 注册、登录
- `/error` — Spring Boot 错误页

### 6.2 认证状态管理

使用 `reactive` + `localStorage`（不引入 Pinia）：

```js
// utils/auth.js
import { reactive } from 'vue'

const state = reactive({
  user: JSON.parse(localStorage.getItem('user') || 'null'),
  token: localStorage.getItem('token') || ''
})

export function isLoggedIn() {
  return !!state.token && !!state.user
}

export function getToken() {
  return state.token
}

export function getUserId() {
  return state.user?.id || ''
}

export function login(user, token) {
  state.user = user
  state.token = token
  localStorage.setItem('user', JSON.stringify(user))
  localStorage.setItem('token', token)
}

export function logout() {
  state.user = null
  state.token = ''
  localStorage.removeItem('user')
  localStorage.removeItem('token')
}
```

### 6.3 路由守卫

```js
router.beforeEach((to, from, next) => {
  const publicPages = ['/login', '/register']
  if (!isLoggedIn() && !publicPages.includes(to.path)) {
    next('/login')
  } else if (isLoggedIn() && publicPages.includes(to.path)) {
    next('/')
  } else {
    next()
  }
})
```

### 6.4 请求拦截

所有 `fetch` 请求统一添加 `Authorization` header：

```js
function authHeaders() {
  const headers = { 'Content-Type': 'application/json' }
  const token = getToken()
  if (token) {
    headers['Authorization'] = `Bearer ${token}`
  }
  return headers
}
```

### 6.5 前端页面流程

```
[未登录] → /login 或 /register
    │
    ├─ 注册 → POST /auth/register → 自动登录 → 跳转首页
    │
    └─ 登录 → POST /auth/login → 存储 Token → 跳转首页

[已登录] → 任何页面
    │
    ├─ 侧边栏底部显示用户名 + 退出按钮
    ├─ 所有 API 请求自动附 Bearer Token
    └─ 退出 → 清除 Token → 跳转 /login
```

## 七、安全性设计

| 风险项 | 防护措施 |
|--------|----------|
| 密码明文存储 | BCrypt 哈希，cost=10 |
| 密码日志泄露 | `LoginRequest` 不包含 password 字段在 toString 中 |
| 暴力破解 | 登录失败统一返回"用户名或密码错误"，不区分具体原因 |
| JWT 密钥硬编码 | 通过 `soul.jwt.secret` 环境变量/YML 配置 |
| 会话固定 | JWT 无 session，天然免疫 |

## 十、Maven 依赖

无需新增依赖。BCrypt 由 `spring-boot-starter-web` 传递引入的 `spring-security-crypto` 提供，JWT 解析使用 `com.auth0:java-jwt` 或手动实现 HMAC-SHA256。

> **推荐添加**：`io.jsonwebtoken:jjwt-api:0.12.5` + `jjwt-impl` + `jjwt-jackson`，或使用 `com.auth0:java-jwt:4.4.0` 简化 JWT 操作。
